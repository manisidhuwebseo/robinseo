Google Adds Branded, Multimodal and Multi-Country Reporting to Search Console API

Google's November 16 update brings three Performance report capabilities into the Search Analytics API. Here is what changed, the documented limits and what SEO teams should do next.

November 17, 20267 min readRobin SEO Editorial Team

Google published a Search Central update on November 16, 2026 that brings three existing Search Console Performance reporting capabilities into the Search Analytics API. The change matters to SEO teams that build custom dashboards, automate reporting or compare search performance across markets and devices.

The update covers branded-query classification, web multimodal search data and multi-country or multi-device filtering. It does not introduce a new ranking factor or promise more traffic. It changes how eligible site owners and developers can request and segment performance data programmatically.

Practical takeaway: Agencies can build more consistent reporting workflows around branded versus non-branded performance, visual-search activity and several countries or devices in a single API request—subject to Google’s eligibility and request limitations.

What Google announced

Google says the three capabilities were already introduced in the Search Console Performance report over the previous year. The November 16 update makes them available through the Search Analytics API after requests from the ecosystem for custom reporting and automation. Read the Google Search Central announcement.

1. Branded and non-branded query classification

The API now supports the brandedClassification dimension, with the values BRANDED and NON_BRANDED. This lets an eligible property compare performance for searches Google classifies as branded versus non-branded without maintaining a hand-written list of brand-name variations.

There are important limits. Google’s API reference says branded classification data starts on February 21, 2026 and is available only for eligible top-level properties with sufficient query and impression volume. Other properties may receive no rows. The API documentation also says branded classification cannot be combined with a query filter in the same request, and the branded filter supports the equals operator only.

For reporting, this means an SEO team should not assume every property will have branded rows or that the classification replaces every query-level analysis. Keep a separate query report for detailed terms, and document the date from which branded classification is available.

2. Web multimodal search reporting

The API now accepts type=webMultimodal for performance data from Google Lens, Circle to Search on Android and image uploads in Google Search. Google also says this data will be available in BigQuery for properties with an active bulk data export.

This is useful for businesses whose products, locations, services or visual content can be discovered through image-led searches. It gives reporting teams a way to examine this category separately from the standard web-search type. It does not mean every image impression becomes a website visit, or that the API reveals every visual query as a complete keyword list.

For a clinic or local service business, the immediate action is not to add decorative images everywhere. Make sure meaningful images have descriptive file names, appropriate alternative text, relevant surrounding copy and a page that answers the visitor’s next question. Measure multimodal data where available, but treat it as one part of search performance.

3. Multi-country and multi-device filters

Google added the filterLists field so one request can match several values for supported dimensions. The API reference currently documents country codes and device types for these lists. That can reduce the need to issue separate requests for each market or device combination.

For a site serving the United States and Canada, a reporting workflow could use the supported country list to examine both markets together, then compare the results with a separate country-level breakdown. Device lists can be used for desktop, mobile and tablet combinations. The goal is not to merge markets into one number and forget the differences; it is to make cross-market monitoring easier while preserving the ability to inspect each market on its own.

What SEO teams should do next

  1. Check property eligibility. Confirm whether the Search Console property is eligible for branded classification. Do not interpret an empty response as proof that the site has no branded demand.
  2. Record the data start date. Branded classification begins on February 21, 2026, so comparisons further back will not have the same classification history.
  3. Separate reporting questions. Use branded classification for the brand split, and query-focused requests for detailed search terms. Respect the documented restriction on combining branded classification with a query filter.
  4. Add multimodal reporting deliberately. If visual discovery matters, request the new type and compare it with the regular web-search view. Do not add the two datasets together without checking their definitions.
  5. Use country and device lists carefully. A combined USA-and-Canada view can help with a regional overview, but keep country-specific reporting for local decisions and content planning.
  6. Document API limits. The Search Analytics API is bounded by internal limits and does not guarantee every data row. The reference documents a maximum row limit of 25,000; a higher limit does not remove all reporting limitations.

How this can improve agency reporting

For an SEO agency, these changes can make recurring reports more useful. Branded versus non-branded segmentation helps separate demand for the business name from broader category discovery. Multimodal reporting can add context for image-led search behaviour. Country and device lists can reduce repetitive requests when reporting across the USA and Canada.

But a dashboard is only as useful as its definitions. Keep the property, date range, search type, filters, aggregation and data limitations visible. Avoid comparing figures from different request configurations as if they were interchangeable. When reporting to a client, explain what each segment includes and what it does not.

For a small business, this is not a reason to commission a complex API project immediately. Start with the Search Console Performance report, identify the questions a manual report cannot answer efficiently, and automate only the repeated analysis that saves time or improves decisions.

Frequently asked questions

When did Google add these Search Analytics API capabilities?

Google announced the API additions on November 16, 2026. Branded classification data itself is available from February 21, 2026 for eligible properties.

What does brandedClassification return?

It classifies eligible search performance data as BRANDED or NON_BRANDED. Google determines the classification; it is not simply a user-maintained regex list.

Can brandedClassification be combined with a query filter?

No. Google’s API reference says branded classification cannot be combined with a query filter in the same request. The branded filter supports equals only.

What is webMultimodal?

It is the Search Analytics API type for Google Lens, Circle to Search on Android and image uploads in Google Search. It can be requested separately from the standard web type.

Can I filter several countries in one API request?

Yes. The new filterLists field supports multiple exact-match values for the country dimension, using three-letter country codes, and for supported device values.

Does the update change Google rankings?

No ranking change was announced. The update expands programmatic reporting options; it does not state that the API features affect ranking systems or guarantee more impressions or clicks.

Official documentation

Read Google’s November 16 Search Central announcement and the updated Search Analytics API query reference. The API reference was updated on November 16, 2026 and includes supported values, limitations and request structure.
