# Robin SEO — New Service Page Publishing Checklist

Use this checklist for every new service or location landing page. Do not publish a page until all applicable checks are complete.

## 1. Keyword and intent
- Confirm the primary keyword, search intent, target country and intended audience.
- Review existing Robin SEO pages to avoid keyword cannibalisation and duplicate intent.
- Use keyword tools and Search Console data where available; never invent search volume, difficulty or ranking potential.
- Define a clear commercial purpose and one primary conversion action.

## 2. Content quality
- Write original, useful content for the target customer; do not spin or pad copy.
- Use one descriptive H1, logical H2/H3 headings, concise paragraphs and useful lists.
- Explain the service, deliverables, process, suitable clients, scope and realistic expectations.
- Add specific, helpful FAQs based on real customer questions.
- Do not invent clients, testimonials, case studies, results, credentials, guarantees or statistics.
- Use accurate US/UK spelling and terminology when those are the target markets.

## 3. Image requirement
- Add at least one original or properly licensed image that directly matches the page title and subject.
- Place a meaningful image near the top/hero where it helps the visitor understand the service.
- Use descriptive, natural alt text; do not stuff keywords.
- Set intrinsic width and height; make the image responsive and compress/optimise it.
- Add Open Graph image metadata and Twitter image metadata when a suitable share image exists.
- Add ImageObject / primaryImageOfPage structured data only when it accurately describes the visible image.
- Verify that the image URL exists and loads on the deployed site. Never use a guessed image URL.

## 4. Navigation and internal links
- Add the new page to the homepage Services section when relevant.
- Add it to the global header / Services navigation.
- Add it to the footer navigation.
- Add contextual links from relevant existing pages; do not force irrelevant links.
- Ensure the new page links back to Home and relevant service pages.
- Use descriptive anchor text and crawlable HTML links.

## 5. On-page SEO and social metadata
- Write a unique title tag and meta description.
- Set one canonical URL that matches the intended clean route.
- Set robots directives appropriately; do not accidentally noindex indexable service pages.
- Add Open Graph and Twitter title, description, URL and image tags as applicable.
- Check language, viewport, favicon and social preview metadata.
- Avoid keyword stuffing and repeated boilerplate.

## 6. Structured data and AI answer readiness
- Add only schema types supported by visible page content, such as Organization references, WebPage, Service, BreadcrumbList and FAQPage when appropriate.
- Ensure JSON-LD is valid JSON and URLs/names match the visible page.
- Do not promise Google rich results or special AI visibility from schema.
- Answer important customer questions directly and clearly.
- Make authorship, business identity, service scope, contact details and claims consistent across the site.
- Include verifiable evidence and first-hand examples only when supplied and approved.
- Do not create fake citations, credentials, reviews or external mentions.

## 7. Technical and conversion checks
- Add clean routing and a deliberate redirect from the .html version if that is the site's URL convention.
- Update sitemap.xml with the canonical clean URL and a sensible lastmod date only when known.
- Check robots.txt, status code, canonical, indexability and redirect behaviour.
- Check mobile layout, keyboard access, contrast, image loading and page speed.
- Ensure WhatsApp/email/contact CTAs work and use the approved contact details.
- Add breadcrumb navigation when appropriate.
- Check for broken links, duplicate IDs, console errors and accidental placeholder text.

## 8. Final verification before marking complete
- Fetch the committed files back from GitHub and verify the final content.
- Validate HTML structure and parse every JSON-LD block.
- Verify image file path and all internal links.
- Confirm homepage, header, footer, sitemap and route all contain the correct URL.
- Confirm Vercel deployment status and test the live page, clean URL, image and sitemap.
- Clearly report what was verified and what could not be verified. Never claim live deployment or indexing unless checked.
